## 01 · 先看结论 {#overview}

移动操作的核心，不是把机械臂装到移动底盘上，而是把“到达目标附近”推进为“选择可操作的身体构型，完成物理交互，并确认结果”。导航、感知、抓取和控制各自有效，仍不代表完整任务可靠。

**本文的工程判断：对个人开发者和中小团队，最有价值的起点是可观测、可恢复的分层系统，而不是一开始就训练包办一切的模型。** 先实现移动抓放闭环，再用学习方法改善明确的薄弱环节。这个取舍是本文建议，不是所有任务的统一最优解。

| 问题 | 判断与阅读入口 |
| --- | --- |
| 技术成熟到哪一步？ | 专用物流已有部署；开放家庭研究仍受对象、环境、示范和辅助条件限制。见第 10 节。 |
| 最容易失败在哪里？ | 导航到操作的交接、接触后的状态更新，以及“动作结束”到“任务完成”的判定。 |
| 三维视觉能贡献什么？ | 操作导向停靠、局部几何闭环、动态物体记忆、几何一致的数据增强。 |
| 第一版怎么做？ | 室内轮式单臂：找物、停靠、抓取、搬运、放置、结果确认。见第 11 节。 |
| 用什么证明进步？ | 完整无干预成功率、干预次数、恢复能力和总耗时，而非只展示成功片段。 |

本文覆盖顺序移动操作、全身协调、开放词汇任务与学习方法。没有进行本文所述系统的独立复现或现场测评；所有性能数字均注明研究条件，不能据此进行跨基准排名。

## 02 · 任务边界：先分清“移动”和“操作”如何耦合 {#scope}

固定机械臂主要解决工作空间内的操作，移动机器人主要解决空间到达；移动操作还要主动选择位置、视角和身体构型。HomeRobot 的开放词汇移动操作（OVMM）将找物、导航、抓取与放置放进一个完整任务，而非孤立评估抓取。[1]

| 层次 | 典型任务 | 新增难点 |
| --- | --- | --- |
| 顺序移动操作 | 到桌边停稳，抓物，运到托盘 | 停靠可达性、重观测、抓放与导航的状态交接 |
| 连续全身协调 | 抓住把手后后退开门；沿长工作台操作 | 底盘与手臂联合轨迹、非完整约束、全身避碰 |
| 足式移动操作 | 在台阶或不平地面上取放、推拉 | 浮动基座动力学、平衡、足端和手部接触协调 |
| 开放世界长程任务 | 跨房间取物、整理、多工位设备操作 | 部分可观测、任务组合、记忆过期与失败恢复 |

Loco-manipulation 更强调运动与操作的耦合，whole-body manipulation 强调整体自由度协调；它们与 OVMM 交叉，但并不等同。轮式、四足带臂和人形都可能承载移动操作，不能只凭机器人形态判断系统能力。

阅读演示时，应追问：目标是否自动发现、环境是否预扫描、底盘是否在任务中真正移动、抓取点或子任务是否由人提供、视频是否展示整段无干预执行。任何一个条件改变，都可能改变结果的含义。

## 03 · 系统架构：让每一步都有进入条件和结束证据 {#architecture}

推荐按世界状态、任务监督、操作导向规划、技能执行和低层保护组织系统。以下是工程设计，不是单篇论文的原样架构。

| 层次 | 输入与输出 | 必须负责的事 |
| --- | --- | --- |
| 状态与世界模型 | RGB-D、激光、编码器、IMU → 几何、物体及机器人状态 | 位置、关系、置信度、观测时间与失效条件 |
| 任务监督 | 语言目标与当前状态 → 子任务 | 前置条件、成功判据、重试预算与恢复 |
| 操作导向规划 | 目标、抓取候选、局部地图 → 停靠与整段轨迹 | 看得见、够得着、路径可行、能够退出 |
| 技能与运动生成 | 抓取、放置或拉门目标 → 轨迹、动作块 | 几何规划、视觉伺服、模仿学习或混合方法 |
| 执行与保护 | 指令、反馈及约束 → 控制输出 | 跟踪、失联处理、碰撞响应、接触和稳定性 |

以 `pick(object)` 为例：进入技能前，需要确认目标仍在原处、夹爪可用、接近轨迹可行；退出时，需要检查物体是否真的被抓住。规划器返回成功，只表示在当前模型下找到了计划；控制器执行结束，也不等于现实目标已经满足。

行为树或状态机适合组织技能切换和恢复；任务与运动规划（TAMP）进一步连接离散动作序列和连续几何参数。PDDLStream 是理解这种接口的经典入口。[7] VLM/LLM 可以协助语义分解，但不应替代碰撞检查、接触反馈或结果验证。

**建议显式维护五类状态：**目标与容器的位置、当前持物状态、门或抽屉的开闭状态、已经完成的步骤、最近失败与观测新鲜度。任务记忆必须由观测更新，不能只沿用模型对“刚才做成了什么”的叙述。

## 04 · 空间表示与停靠：最近的位置未必最好操作 {#geometry}

### 分层地图，而不是一个表示解决全部问题

| 表示 | 主要用途 | 不能替代的能力 |
| --- | --- | --- |
| 2D 占据栅格 / 代价地图 | 底盘通行与全局导航 | 悬空障碍、机械臂扫掠空间、持物碰撞 |
| 点云、TSDF、ESDF | 局部三维几何与距离查询 | 动态残留清理、未知区域处理、接触参数 |
| 物体级场景图 | 按语义找物、关系推理与任务记忆 | 接触精度、物体状态验证 |
| 对象局部坐标与关节模型 | 抓取姿态、把手、抽屉和转轴 | 标定误差、遮挡与不确定性管理 |

ConceptGraphs 将带位姿的 RGB-D 观测关联为物体级三维场景图；DovSG 将动态更新纳入长期语言引导的移动操作。[5][6] 这类表示的价值不仅是“记住杯子在哪里”，还包括杯子移动后使旧位置失效、更新支撑关系，并在证据不足时保留不确定性。

nvblox 提供从深度与位姿到三维重建和导航地图的工程入口。[4] 但渲染漂亮的 3DGS 不自动具有可靠的碰撞几何：薄结构、未观测区域、尺度和动态物体仍需单独验证。

### 把定位误差带进操作问题

```text
T_world,ee = T_world,base · T_base,arm · T_arm,ee
```

末端误差同时受底盘定位、机械安装外参、关节状态和目标估计影响。量级示例：在 0.6 m 距离上，1° 方向误差对应约 0.6 × sin(1°) ≈ 10.5 mm 的横向偏差。这是计算示例，不是设备实测，也不代表误差应直接线性相加。

ROS REP-105 区分连续但可漂移的 `odom` 与可能发生重定位跳变的 `map`。[3] 操作阶段应保持局部坐标和时间一致，避免把全局重定位突变直接传入末端跟踪。

### 停靠要评估整段操作

导航器能到桌边，不代表机械臂能够完成“接近—抓住—提起—撤离”；初始姿态有逆解，也不保证后续轨迹无碰撞。

```text
建议建模：
b* = arg min_b [导航代价 + 操作代价 + 不确定性代价 + 风险代价]
约束：可达、可见、全路径无碰撞、接触与稳定条件可满足。
```

各代价项需按任务设置权重并处理量纲。先筛掉不可行候选，再比较路径长度、操作裕量与观察质量。对差速底盘，还要考虑无法直接横移的约束。主动感知则把“换位置再看一次”纳入动作选择，目标是提高任务成功率，不是单纯重建更多表面。

**建议对照实验：**比较最近点停靠、仅检查 IK、加入整段碰撞与视角约束、再加入局部视觉闭环四种方案。固定对象和任务，扰动停靠平移与朝向，统计整段任务成功率和耗时。

## 05 · 抓取与放置：检测、位姿和动作不是同一个输出 {#grasping}

开放词汇检测解决“哪个是杯子”；分割与深度帮助定位；抓取生成还要决定接触点、夹爪朝向、宽度与接近方向。倒水与搬运对同一个杯子的抓法也可能不同。

FoundationPose 支持在物体模型或相应参考视图条件下进行新物体 6D 位姿估计与跟踪，并非无输入条件地恢复任意对象。[31] GraspGen 将扩散生成和判别筛选用于 6-DOF 抓取。[32] 两者都是局部能力组件，不能直接等同于可执行的移动操作系统。

| 阶段 | 应检查的条件 | 常见误判 |
| --- | --- | --- |
| 生成候选 | 目标分离、夹爪尺寸、功能部件 | 检测正确就认为可以抓 |
| 接近与抓取 | 预抓取可达、整段无碰撞、误差裕量 | 初始逆解存在就认为动作可行 |
| 提起与运输 | 上方空间、持物碰撞模型、稳定携带构型 | 抓住后仍沿用空夹爪碰撞模型 |
| 放置与确认 | 支撑面、空闲区、物体最终状态 | 夹爪张开就标记任务成功 |

首版优先选择轻、硬、不透明、容易用双指夹爪夹持的对象。透明、柔性、精细插接等任务应作为独立扩展，避免同时引入感知、接触和学习的不确定性。

## 06 · 全身控制、接触与时延 {#control}

### 联合利用底盘与手臂

```text
平面轮式单臂的简化构型：q = (x_b, y_b, θ_b, q_arm)
末端速度：v_ee = J_base(q) · q̇_base + J_arm(q) · q̇_arm
差速约束：ẋ = v cos θ，ẏ = v sin θ，θ̇ = ω
```

这里的表达用于说明运动学分工，并非可以直接下发的控制程序。底盘后退而手臂前伸，可以在世界坐标中保持末端近似不动，但仍要满足轮地约束、关节限位、避碰和稳定性。

MoveIt 官方已经提供差速底盘与机械臂协调教程，并明确建议纯导航使用 Nav2。[2] 因此，“MoveIt 只能规划固定机械臂”并不准确。能生成联合路径，也不代表底层驱动已经支持可靠同步执行。

| 路线 | 适合的起点 | 主要边界 |
| --- | --- | --- |
| 顺序规划 | 停稳后抓放，建立可诊断基线 | 可能错失需要同步移动的动作 |
| 运动学 QP | 实时分配底盘与关节速度 | 局部解不等于长程可达 |
| MPC | 在预测窗口内协调任务和约束 | 对模型、初始化、求解时延敏感 |
| 学习型全身控制 | 仿真训练复杂身体协调 | 需要实机迁移、约束和失败验证 |

OCS2 是最优控制工具，cuRobo 是 GPU 运动生成与碰撞计算的重要候选。[8][10] 具体底盘运动模型、控制接口与版本必须另行确认。UMI on Legs 展示了真人示范学习上层操作、仿真训练身体跟踪的分层思路；其高层动作也仍受可达性约束。[11]

### 接触任务不能只靠位置轨迹

开门、拉抽屉、插接或擦拭时，几何和摩擦误差会改变接触力。阻抗或导纳控制需要与真实执行器开放的力矩、速度或位置接口匹配，不能把一段柔顺控制公式当成通用控制器。

```text
概念性导纳关系：M_d ë + D_d ė + K_d e = F_external − F_desired
```

接触、卡住、滑脱与抓牢是不同状态，应触发不同恢复策略。本文不提供可直接用于人体接触或高负载作业的控制参数。

### 把推理与保护分开

语义理解可以低频或事件触发；几何跟踪、底盘与手臂控制、异常保护必须按各自时延预算运行。RTC 在继续执行已有动作时生成后续动作块，并处理跨块衔接，说明“动作输出频率”不能当作“大模型推理频率”。[16] Perceptive HTMPC 可作为多速率系统的补充阅读，但本文不把其具体频率当成行业最低规范。[9]

Nav2 Collision Monitor 提供绕过规划器的减速或停止机制，官方明确它不构成硬实时安全认证。[30] 失联、过期指令和接触异常不能依赖云端模型及时响应；真实设备仍需适当的物理急停、限速、监督和风险评估。

## 07 · 学习与 VLA：先问系统究竟学会了哪一层 {#learning}

| 工作 | 值得借鉴的能力 | 不应省略的条件 |
| --- | --- | --- |
| Dobb-E（2023） | 家庭示范采集与快速任务适配 | 10 个家庭、109 项任务、81% 是作者适配后的技能结果，不是零样本跨房间服务。[14] |
| Mobile ALOHA（2024） | 底盘与双臂遥操作、联合模仿 | 论文描述每任务约 50 条示范；自主技能与遥操作演示需要分开看。[12] |
| OK-Robot（2024） | 开放词汇语义、导航与抓取模块集成 | 10 个家庭 pick-and-drop 的 58.5% 包含预扫描、顺序执行等条件；不是持续更新地图的通用系统。[13] |
| UMI on Legs（2024） | 操作策略与身体控制分层迁移 | 真人示范与仿真控制的接口有价值，但仍需检查高层目标可达性。[11] |
| π0.5（2025） | 异构数据共训练与跨环境任务 | 应区分按步骤计分的完成度与完整任务成功率；不与其他系统百分比直接排名。[15] |

动作空间必须明确：关节位置、关节速度、末端增量、绝对位姿和底盘速度不能简单拼成“统一动作”。数据应记录坐标系、单位、时间戳、控制周期和相机标定。

**记忆与组合泛化。** MEM（2026-03-03）将短期观测与长期语言记忆结合，作者展示了需要最长约 15 分钟记忆的任务。[17] 这支持记忆对长程任务的价值，但语言状态仍不能取代精确几何与真实反馈。

π0.7（2026-04-16）的官方空气炸锅示例区分了三个条件：仅零样本提示未完整完成，逐步语言指导后改善，再利用这些指导适配高层策略。[18] 把三者统称为“零样本自主完成”，会掩盖关键条件。

**公开程度要单独核查。** openpi 的公开模型列表与厂商演示不是同一件事。[19] 论文、视频、推理代码、权重、训练代码、数据及标定说明，是不同层级的可复现材料；本报告没有下载并运行全部项目。

## 08 · 三维几何进入策略与数据：HoMMI 和 MoMaSplat {#geometry-learning}

### HoMMI：视角信息要与身体约束一起处理

HoMMI（RSS 2026）用第一人称感知增强手持示范采集，通过三维表示、观察目标点与约束感知的全身控制，缓解人到机器人的观测和动作差异。[20] 作者的对照说明：仅腕部视角容易缺少搜索与双臂协调上下文；仅头部视角又难以提供近场操作精度。

本文的启发是：主动感知不只是增加一个相机，而是把“看哪里”与“身体能如何执行”共同设计。对不同机器人的迁移，仍需验证视野、运动学和控制接口。

### MoMaSplat：不能只增强图像而忘记动作

MoMaSplat 于 2026-11-05 公开预印本。它分别重建背景与被操作物体，在新的底盘位姿重渲染示范，并同步重定向动作。[21] 作者在三个场景、五项真机任务上报告，未见位姿的平均成功率为 37%，其最强比较基线为 17%。这是特定作者实验下的结果，既说明改进空间，也说明可靠性仍有限。

本次核查了论文正文，但没有验证可直接运行的完整代码。它值得研究的不是“多生成一些图”，而是图像、动作、接触状态、相机外参与机器人可达性是否一起保持一致。

**建议实验：**固定同一批原始示范，对比不增强、仅图像扰动、仅动作扰动与几何一致增强；在未见停靠位姿测试，并单独统计接触前和接触后的失败。渲染逼真度只能作为辅助指标，不能替代任务成功。

## 09 · 基准与仿真：先对齐测试问题，再比较成绩 {#benchmarks}

| 基准 | 主要用途 | 解读边界 |
| --- | --- | --- |
| HomeRobot OVMM | 开放词汇找物、导航、抓放集成 | 早期基线分数不是当前能力上限。[1] |
| BEHAVIOR 2026 | 家庭长程任务和物体状态改变 | 允许 RGB、深度和本体感知；不能把真值物体位姿直接交给策略。主分数含部分完成积分。[24] |
| MobileManiBench | 局部移动操作技能与 VLA 架构 | 300K 轨迹；平均 160 帧、30 FPS 对应约 5.3 秒，不能代表跨房间长任务。[22] |
| EBench | 按能力与泛化维度诊断 | 26 类任务，并按泛化维度展开实例；应看分项而非单一平均数。[23] |
| RoboCasa365 | 厨房技能与组合任务 | 具体场景划分和排行榜口径会变，复现前需固定版本；本次不据动态榜单排名。[25] |

仿真应记录观测权限、控制接口、碰撞与抓取模式。拿到真值位置、使用几何附着抓取、暂停仿真等待模型输出，都可能高估真实闭环能力。每个简化都应写进实验协议。

三类用途可以分开推进：用几何仿真检查规划约束，用并行仿真学习身体控制，用可控扰动批量制造失败场景。涉及接触时，还要验证质量、摩擦、刚度和执行器建模；视觉逼真并不能消除物理差距。

## 10 · 商业部署与平台：看工作流，不只看演示 {#deployment}

DHL 的 2025-05-13 官方公告确认 Stretch 已在北美商业部署并向其他地区扩展，报告最高 700 箱/小时；“新增 1,000 多台”对应 MOU 下的未来计划，不能当成该公告时点已交付数量。[26] 这支持受约束纸箱卸货任务的部署价值，不代表任意对象、家庭环境都具备同样成熟度。

利物浦大学的移动机器人化学家研究报告八天执行 688 次实验，是多工位长时间自动化的重要例子，但依赖具体实验流程和环境适配。[27]

| 场景 | 移动可能带来的价值 | 必须补齐的工程验证 |
| --- | --- | --- |
| 物流卸箱与周转 | 对象族、路径和流程相对明确 | 混杂对象、异常恢复、吞吐和输送系统集成 |
| 多工位设备上下料 | 一个操作单元服务多个工位 | 停靠、夹具、设备状态、节拍与可用率 |
| 实验室自动化 | 分散仪器与可形式化流程 | 样品身份、精细操作、长时状态一致性 |
| 家庭整理 | 需求广，环境变化大 | 遮挡、易碎物、开放指令与人机共处 |

表中的机会是任务结构分析，不是市场规模或回报预测。还应与固定机械臂加输送线、改造环境、多固定工位或人工搬运比较；跨工位移动带来的收益必须超过新增复杂度。

平台资料可参考 Hello Robot Stretch 与 PAL Robotics TIAGo Pro，但选型要检查真实控制接口、负载力矩、标定、驱动维护和保护能力。[28][29] **Hello Robot Stretch 与 Boston Dynamics Stretch 是不同产品，不能混用规格和部署数据。**本文不构成硬件采购推荐。

## 11 · 原型路线与验收：先做可靠的跨桌搬运 {#prototype}

建议的公开原型任务：把自然语言指定的物体，从一张桌子搬到另一张桌子的托盘，并自行确认结果。以室内轮式单臂、双指夹爪、RGB-D、必要的定位传感器和 ROS 2 为通用条件；首版在操作时停稳底盘。

| 阶段 | 必须交付的能力 | 验收依据 |
| --- | --- | --- |
| M1 固定底盘抓放 | 标定、近场识别、抓放和后验确认 | 分清视觉、规划、执行与抓持失败 |
| M2 导航后抓放 | 停靠后重观测；更新持物碰撞模型 | 不同起点和摆放下完成整段任务 |
| M3 操作导向停靠 | 选择可操作位姿，失败后局部换位 | 同一测试集优于最近点停靠基线 |
| M4 动态状态与恢复 | 应对目标移动、抓空、滑脱和放置区占用 | 记录恢复成功、额外耗时与人工介入 |
| M5 局部全身协调 | 对开门等任务加入底盘与手臂同步 | 在接触和误差扰动下保持可控 |
| M6 学习与泛化 | 示范训练局部技能，测试新布局与位姿 | 改善具体指标，不以人工指导掩盖失败 |

机器人端应保留通信、状态与保护反馈。重模型可由工作站承担，但观测和动作必须带时间戳，过期结果不能继续执行。openpi 所查 README 给出的单 GPU 参考显存为：推理大于 8 GB、LoRA 大于 22.5 GB、全量微调大于 70 GB。[19] 这些是该项目参考配置，不是对任意 batch、视角数量与训练设置的保证。

### 一个任务指标不够

```text
完整成功概率 = Π_i P(第 i 步成功 | 前面的步骤均成功)
示例：0.95^10 ≈ 59.9%；0.99^10 ≈ 90.4%。
```

这是条件概率链式分解的量级示例，不假定各步骤独立，也不是某台机器人的成绩。长任务除了提升单步质量，更需要发现失败和恢复。

| 指标 | 建议口径 |
| --- | --- |
| 完整任务成功率 | 固定时限与重试预算内，全部目标满足且无人工干预 |
| 人工介入 | 每小时次数、总时长，区分指导、重置、移障和遥操作 |
| 总任务耗时 | 中位数与 P95，包括推理等待、重定位、重试与恢复 |
| 恢复能力 | 故障可检测比例、恢复成功比例、额外耗时 |
| 操作质量 | 抓牢、滑脱、放置误差、对象或环境是否受损 |
| 泛化 | 新物体、新摆放、新房间、新任务和新形态分别统计 |

固定测试划分、初始分布与辅助信息。对停靠偏差、遮挡、光照、目标移动和放置区占用分别扰动，再考虑组合扰动；报告试验次数与置信区间，保留失败样本而非只保留成功视频。

## 12 · 值得继续投入的三个问题 {#research-agenda}

**操作导向停靠与主动观察。**假设：加入整段可达性、视角与误差裕量，可提高完整任务成功率。用最近点、IK、轨迹碰撞、视角和局部闭环逐级消融。这是最适合形成近期工程作品的路线。

**物体级动态三维记忆。**假设：显式更新身份、位置、状态和观测有效期，能减少错误目标与重复动作。对比静态图、动态图、带置信度与失效机制的动态图，重点检查物体搬动后的重新发现。

**几何一致示范增强。**假设：重建、视角合成和动作重定向可降低停靠精度及真实示范量的要求。必须验证接触阶段的物理可行性，并将真实任务结果与图像指标分开报告。

阅读顺序建议：HomeRobot / OK-Robot 理解系统和失败；MoveIt / OCS2 理解执行层；Mobile ALOHA / π0.5 / RTC 理解数据和时序；HoMMI / MoMaSplat / BEHAVIOR / EBench 确定研究变量与协议。

**局限声明：**本文是公开资料调研与工程分析，不是认证报告、采购结论或独立复现实验。未知兼容性不等于不支持；材料公开不等于一键复现；演示完成不等于持续可靠运行。涉及具体版本、权重、许可或排行榜时，实际实施前应再次锁定和检查。
